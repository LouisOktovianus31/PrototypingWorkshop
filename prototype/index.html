Target yang diuji

Checklist Acceptance Criteria

PRODUCT_SPEC.md Section 5. Buka di state 3, jangan beri penjelasan apa pun dulu.

Titik yang perlu diperhatikan saat observasi

  • FR-002 di posisi #1 padahal marginnya positif. Apakah tester paham kenapa oversell lebih mendesak daripada SKU yang sedang rugi?
  • MU-003 badge merah tapi stock 109 unit / 54,5 jam. Apakah badge merah untuk alasan margin terbaca jelas, atau malah dikira salah baca stock?
  • SK-007 di 6,2 jam = kuning, bukan merah. Threshold 6 jam belum divalidasi ke user riil (PRODUCT_SPEC Section 7 #3). Tanya: 6,2 jam itu rasanya mendesak atau masih santai?
  • BC-999 menampilkan "Stock aman", bukan angka jam. Cek apakah ini kebaca wajar atau justru terasa seperti data hilang.
  • State 6 (Budget Kritis). Badge campaign merah sementara list SKU tidak berubah. Apakah tester sadar itu dua level informasi yang berbeda?

Yang belum ada di prototype ini (jangan diuji)

  • Eksekusi apa pun ke seller center — tidak ada tombol delist/replenish yang benar-benar bekerja.
  • Auto-dismiss toast 6 detik, scroll-to-SKU, dan animasi transisi status (ada di versi React).
  • Multi-brand switcher, login, dan integrasi API live (PRODUCT_SPEC Section 6).

Versi interaktif (input budget yang benar-benar menghitung, loading transisi, toast auto-dismiss) ada di app React: npm run dev. Prototype static ini untuk review visual cepat dan sesi testing tanpa setup.
